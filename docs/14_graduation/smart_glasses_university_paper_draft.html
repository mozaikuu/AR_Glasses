Abstract

Background: Hands-free campus assistance is difficult with phone-first systems because they divide user attention and do not consistently integrate voice, navigation, and wearable hardware. Objective: This paper presents Smart Glasses Distilled, a modular wearable-assistant platform that unifies multimodal processing and client interoperability. Methods: The implementation combines a FastAPI gateway, a cloud-first LLM adapter (Cerebras), speech transcription using Google SpeechRecognition with retry diagnostics, MCP-style vision tooling using Moondream, Unity-based navigation intent routing, and ESP32-compatible processing with optional WAV retrieval. Results: Repository evidence shows 67/67 selected Python unit tests passing with 79% total coverage, integration smoke tests passing (1/1), firmware native tests passing (5/5), Unity EditMode test step passing, live HIL endpoint checks passing (13/13), and cross-device audio matrix checks passing (10/10). Conclusion: Smart Glasses Distilled demonstrates a reproducible, testable architecture for multimodal wearable assistance and provides a strong engineering baseline for formal user studies and quantitative latency benchmarking.

1. Introduction Polish narrative for final submission

Wearable assistants are often fragmented: some products prioritize voice interaction, others focus on visualization, and others provide isolated indoor navigation features. In university and campus settings, users need an integrated experience that can accept speech, understand intent, trigger navigation, and return contextual responses across multiple devices (headset, browser, mobile, and embedded hardware).

Smart Glasses Distilled addresses this integration problem through a gateway-centered architecture and contract-first API design. The project is built as a graduation-ready engineering system, with emphasis on reproducibility, validation artifacts, and practical deployment workflows.

Contributions statement (ready for submission):
This work makes four contributions: (1) A unified multimodal backend architecture that serves Unity, browser, mobile, and ESP32 pathways through one FastAPI gateway; (2) A practical speech-vision-language interaction pipeline with wakeword-aware control and MCP-style vision tooling; (3) A navigation workflow that connects destination normalization on the server with local Unity NavMesh execution; (4) A layered validation protocol combining unit tests, integration tests, firmware native tests, Unity EditMode checks, and live HIL endpoint verification.

Recent wearable systems provide partial solutions for capture, display, or voice interaction, but often do not provide an end-to-end multimodal orchestration architecture suitable for student-scale replication. Smart Glasses Distilled positions itself as an applied integration framework rather than a single-model novelty.

2.2 Indoor Navigation in Smart Buildings

Many indoor systems rely on infrastructure-heavy localization setups or mobile-only interaction. This project uses server-side destination routing with Unity-side path execution, balancing centralized intent logic with low-latency local movement behavior.

2.3 Multimodal AI and Tool-Oriented Reasoning

Tool-augmented assistants are increasingly adopted to improve factual grounding and actionability. In this project, LLM generation is combined with bounded response shaping, optional MCP tool invocation for vision, and typed API contracts for deterministic downstream actions.

3. Methodology Quantitative expansion planned

3.1 System Architecture Overview

The runtime consists of a primary process (start.py launching app.api.gateway:app) and an optional MCP sidecar for vision tools. The gateway routes requests to assistant, navigation, audio, and QR services. Clients include Unity MetaQuest, browser/Streamlit, mobile bridge, and ESP32 firmware.

3.3 Speech and Language Pipeline

Incoming audio is decoded from base64 payloads, normalized, and transcribed. The service tracks diagnostics such as retry attempts, sample format, and provider status. The resulting text is then processed by the assistant service and sent to the LLM adapter for concise answer generation.

T_total = T_stt + T_route + T_llm + T_tts(optional)

This decomposition is used as the latency model for upcoming micro-benchmarks.

3.4 Vision Pathway

The gateway can call MCP vision tools in two modes: live camera capture (/tools/vision/capture-moondream) and image analysis (/tools/vision/analyze-image-moondream). If image analysis fails, the assistant returns an explicit degraded-response message to preserve usability.

3.5 Navigation and AR Execution

Navigation destinations are loaded from navigation.json (12 curated location IDs in current dataset). The server resolves destination aliases and creates session-based instructions; Unity executes movement in-scene using NavMesh.

3.6 Hardware and Device Integration

The project supports two ESP32 communication modes: phone relay over BLE and direct Wi-Fi backend access. For voice responses, the ESP endpoint can return both text and a temporary TTS URL for WAV retrieval, preserving compatibility with existing firmware expectations.

5. Discussion

The project demonstrates strong engineering reliability for a graduation-scale multimodal assistant. The strongest evidence is the consistency of cross-layer validation: software unit testing, firmware tests, Unity checks, and live API sweeps all pass in the latest artifact set.

5.1 Strengths

  • - One gateway contract serves multiple device types without major API drift.
  • - Typed request models and compatibility responses reduce integration failures.
  • - Validation artifacts are reproducible and auditable for defense review.
  • - Navigation, QR telemetry, and ESP pathways are all covered by live checks.

5.2 Current Limitations

  • - Navigation sessions are in-memory only and not yet persistent.
  • - Formal route-accuracy and localization-error studies are not yet completed.
  • - Per-stage latency telemetry is limited in current logs.
  • - Security controls are baseline and require hardening for public deployment.

6. Conclusion

Smart Glasses Distilled provides a practical and reproducible framework for multimodal wearable assistance in campus-like environments. The implemented architecture is stable across software and hardware pathways, and current validation artifacts show full pass status across major functional checks. The next phase should focus on formal user studies, route-level navigation metrics, and finer-grained latency instrumentation to convert engineering reliability into publication-grade empirical evaluation.
